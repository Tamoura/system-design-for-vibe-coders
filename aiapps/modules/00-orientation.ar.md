# 0.1 — ما الذي يلزم لإطلاق وكيل بمستوى المؤسسات: دورة حياة التسليم والطبقات وكيف تعمل الدورة
*المستوى: 🟢 مبتدئ* · *المتطلبات: لا يوجد* · *الطبقة: Delivery*

## ⚡ الدرس في دقيقة
- إطلاق الوكيل **دورة حياة** وليس عملية بناء فحسب: استكشف، وصمّم، وابنِ، وقيّم، وأمّن، وأطلق، وشغّل، وسلّم (hand over).
- معنى **بمستوى المؤسسات (enterprise-grade)** هو عشر خصائص تستطيع أن تقدّم دليلًا عليها، مثل أن يكون الوكيل موثوقًا وخاضعًا للحوكمة وقابلًا للدعم. عبارة «نحن حريصون» ليست دليلًا.
- **روبوت الدردشة (chatbot)** يجيب، و**سير العمل (workflow)** يتبع مسارًا تحدّده شيفرتك، و**الوكيل** يختار خطواته بنفسه. استخدم أبسط خيار ينجح.
- كثيرًا ما تتعثّر التجارب التشغيلية (pilots) بعد مرحلة البناء، لأن العرض التجريبي لا يثبت إلا النصف الأول.
- الدورة مجموعة قراءة، بمعدل وحدة أسبوعيًا، على مشروع عميل **خيالي** هو نجم ديسك (Najm Desk). وتعمل المختبرات دون اتصال، كما تعمل دون أي تغيير على الواجهة البرمجية الحقيقية.
- يكتب Claude Code جزءًا كبيرًا من شيفرتك؛ ومع ذلك يجب أن تشرح كل سطر يُطلَق.

## 🧭 لماذا يهم
تخيّل تجربة تشغيلية (pilot) في بنك نجم (Najm Bank) لم تصل قط إلى مستخدميها. (القصة افتراضية، مثل كل قصص نجم.) بنى فريق صغير **اسأل الموارد البشرية (Ask HR)**، وهو روبوت دردشة يعمل على سياسات الموارد البشرية، وبعد ستة أسابيع صفّقت اللجنة التوجيهية للعرض التجريبي. ثم اصطدم المشروع بالنصف الثاني من دورة الحياة. فسألت **سارة (Sara)**، مسؤولة حماية البيانات (Data Protection Officer)، عن بيانات الموظفين التي ترسلها الموجّهات إلى مزوّد النموذج. لم يعرف أحد. وطلبت **ليلى (Layla)** تقييم المخاطر. ولم يكن هناك تقييم. وسأل فريق **حمد (Hamad)** عمّا يمنع مستندًا ملصقًا من إعطاء الروبوت تعليمات جديدة (حقن الموجّه (prompt injection)، الوحدة 13). وسألت **مها (Maha)** عمّن سيتلقى نداء التنبيه؛ فكان الجواب «المطوّر»، وقد انتقل إلى فريق آخر. وكان الموجّه (prompt) في خلية دفتر ولا اختبارات له، فلم يجرؤ أحد على تعديله. وبعد أربعة أشهر أُوقفت التجربة التشغيلية. النموذج لم يفشل قط. الذي فشل هو التسليم.

وفق ما نُشر، قضت هيئة تحكيم في كولومبيا البريطانية (British Columbia) في قضية *Moffatt v. Air Canada* (2024) بأن شركة الطيران مسؤولة عن معلومات خاطئة قدّمها روبوت الدردشة في موقعها إلى أحد العملاء. هذا حكم واحد في ولاية قضائية واحدة، لكن خطّط وكأن مؤسستك ستُسأل عمّا يقوله وكيلها، واسأل فريقك القانوني مبكرًا. إن عبارة «يعمل في العرض التجريبي» هي بداية العمل.

## 📐 كيف يعمل

### 🟢 الأساسيات

**دورة حياة التسليم.** يمرّ مشروع الوكيل بثماني مراحل. تنتهي كل مرحلة بمُخرَج تستطيع أن تسلّمه لشخص آخر، ولكل مرحلة موضع في هذه الدورة.

```mermaid
flowchart RL
    A["الاستكشاف<br/>الوحدة 6<br/>(Discover<br/>Module 6)"] --> B["التصميم<br/>الوحدة 7<br/>(Design<br/>Module 7)"]
    B --> C["البناء<br/>الوحدات 1 إلى 5 و8 إلى 11<br/>(Build<br/>Modules 1 to 5, 8 to 11)"]
    C --> D["التقييم<br/>الوحدة 12<br/>(Evaluate<br/>Module 12)"]
    D --> E["التأمين<br/>الوحدة 13<br/>(Secure<br/>Module 13)"]
    E --> F["الإطلاق<br/>الوحدة 14<br/>(Ship<br/>Module 14)"]
    F --> G["التشغيل<br/>الوحدة 15<br/>(Operate<br/>Module 15)"]
    G --> H["التسليم<br/>الوحدتان 15 و16<br/>(Hand over<br/>Modules 15 and 16)"]
    D -.->|"دون المستوى المطلوب (below the bar)"| C
    G -.->|"ما نتعلّمه (what we learn)"| A
```

| المرحلة | السؤال الذي تجيب عنه | ما تسلّمه |
|---|---|---|
| **الاستكشاف** | ما المشكلة الحقيقية، وهل ينبغي أن يكون الحل وكيلًا؟ | موجز الوكيل (agent brief) |
| **التصميم** | ما الذي يجوز له فعله بمفرده، ومن يوافق على ماذا؟ | المعمارية والنطاق المتفق عليه |
| **البناء** | كيف يتكامل النموذج والموجّهات والأدوات والحلقة (loop)؟ | وكيل يعمل |
| **التقييم** | هل هو جيد بما يكفي، وهل سننتبه إذا توقف عن ذلك؟ | مجموعة التقييم (eval set) وبوابة التكامل المستمر (CI gate) |
| **التأمين** | ما الذي قد يسوء، أو يمكن دفعه إلى السوء عمدًا، ومن يعتمد؟ | نموذج التهديدات (threat model) والحواجز الوقائية (guardrails) واعتماد الحوكمة |
| **الإطلاق** | كيف يصل إلى المستخدمين، وكيف نتراجع عنه؟ | خط النشر وخطة الإصدار والميزانية |
| **التشغيل** | كيف نراه ونصلحه ونحسّنه؟ | لوحات المتابعة ودليل التشغيل (runbook) |
| **التسليم** | من يملكه غدًا؟ | التدريب ونموذج الدعم والقبول (acceptance) |

تعلّمك الدورة لبنات البناء أولًا، لأنك لا تستطيع تحديد نطاق (scope) ما لا تستطيع بناءه؛ ثم تعود الوحدة 6 إلى الاستكشاف. ودورة الحياة أيضًا حلقة: فالتقييم الفاشل يعيدك إلى البناء، وما يعلّمك إياه التشغيل يغذّي الاستكشاف التالي.

**ماذا يعني «بمستوى المؤسسات».** تبقى العبارة تسويقًا حتى تحوّلها إلى أسئلة يستطيع المتشكّك طرحها. وهذه عشرة منها، لكل سؤال الدليل الذي يجيب عنه.

| الخاصية | سؤال المتشكّك | الدليل الذي تستطيع تقديمه |
|---|---|---|
| **موثوق** | هل يتدبّر أمره حين تضطرب أداة (tool) أو الشبكة؟ | المهلات (timeouts) وإعادة المحاولات المحدودة وحدود الحلقة |
| **آمن** | هل يستطيع أحد دفعه إلى ما لا ينبغي أن يفعله؟ | نموذج التهديدات واختبارات الحقن |
| **خاضع للحوكمة** | من وافق عليه، ومن يحق له تغييره؟ | تقييم المخاطر والاعتماد (sign-off) |
| **قابل للمراقبة** | هل تستطيع أن ترى ما فعله ولماذا؟ | تتبّع (trace) لكل خطوة |
| **قابل للدعم** | من يتلقى مكالمة الثالثة فجرًا، وماذا يفعل؟ | دليل التشغيل وجدول المناوبة |
| **مضبوط التكلفة** | كم تكلّف المحادثة، وما الذي يوقف التكلفة المنفلتة؟ | التكلفة لكل طلب والميزانيات والسقوف |
| **مُختبَر** | هل كسر التغيير شيئًا؟ | اختبارات الوحدة ومجموعة التقييم وبوابة التكامل المستمر |
| **موثَّق** | هل يستطيع القادم الجديد أو المدقّق متابعته؟ | المواصفات (specification) وسجلات القرار |
| **مقبول** | هل وافق العميل على أنه اكتمل؟ | معايير القبول الموقّعة |
| **قابل للتحسين** | هل يجعله الاستخدام الحقيقي أفضل؟ | ملاحظات تتدفق إلى مجموعة التقييم |

ضعيف: «إنه بمستوى المؤسسات. نستخدم نموذجًا قويًا واختبرناه.» قوي: «هذه مجموعة التقييم، وفحص التكامل المستمر (CI check) الذي يمنع الإصدار حين تنخفض الدرجة، ونتيجة الأسبوع الماضي، والإخفاق الذي أضفناه بعد التجربة التشغيلية.» الإجابة القوية مجموعة من المُخرَجات يستطيع شخص آخر فتحها. وتختلف أوزان الخصائص من عميل لآخر: فمساعد القراءة فقط يحتاج حوكمة أقل من وكيل يكتب في نظام التذاكر.

**روبوت الدردشة وسير العمل والوكيل.** هذه لمحة أولية؛ وتعلّم الوحدات 1 و5 و8 كلًّا منها كما ينبغي. **روبوت الدردشة** يجري استدعاءً واحدًا للنموذج في كل دور، ويعيد إرسال المحادثة في كل مرة، ولا يملك أدوات.

أما **سير العمل** فينظّم استدعاءات النموذج والأدوات على مسار تحدّده شيفرتك؛ فهو قابل للتنبؤ وقابل للاختبار وأرخص، ويحل جزءًا كبيرًا من المشكلات الحقيقية.

وأما **الوكيل** فيترك النموذج يوجّه عمليته بنفسه: يختار الأداة التالية، ويقرأ النتيجة، ويكرر حتى يقرر أنه أنجز. وهذه المرونة هي مصدر مخاطرته أيضًا، ولذا تحتاج الوكلاء إلى حدود وتتبّع (traces) وتقييمات. ويتبع التمييز بين سير العمل والوكيل مقال Anthropic «Building effective agents»، الذي ينصح بالبحث عن أبسط ما ينجح؛ أما «روبوت الدردشة» فتسمية خاصة بهذه الدورة.

### 🟡 التعمق أكثر

**مثال تطبيقي: ربط «اسأل الموارد البشرية» بدورة الحياة.** سطر واحد لكل مرحلة: ما الذي حدث، وأي مُخرَج موجود.

| المرحلة | ما الذي حدث | المُخرَج |
|---|---|---|
| الاستكشاف والتصميم | «روبوت لأسئلة الموارد البشرية»؛ دون مقابلات؛ واختير الاسترجاع (retrieval) في اليوم الأول | لا شيء |
| البناء | دفتر وإطار عمل؛ ويعمل جيدًا | الدفتر |
| التقييم | عشرة أسئلة جُرّبت يدويًا | لا شيء محفوظ |
| من التأمين إلى التسليم | لم تُناقَش؛ عرض من حاسوب محمول؛ بلا مالك | لا شيء |

كانت مرحلة البناء المرحلة الوحيدة التي لها مُخرَج مكتمل، وهذا شكل مألوف للتجربة التشغيلية المتعثرة. وتتكرر الأسباب: لم يحدّد أحد معنى النجاح، فصارت المراجعات آراء؛ ووصل أصحاب المخاطر (risk owners) متأخرين فاعترضوا عليه؛ ولم يقِس شيء الجودة، فلم يستطع أحد تغيير أي شيء بأمان؛ ولم يملك أحد النظام العامل ولا فاتورته. والدفاع الرخيص هو **التحليل الاستباقي للفشل (premortem)**: قبل أن تبدأ، اكتب لكل مرحلة «بعد ستة أشهر أُوقف هذا المشروع لأن…»، ثم خطّط ضد أرجح الإجابات.

**الطبقات.** يحمل كل درس وسمًا للطبقة التي يعمل عليها؛ وقد يحمل الدرس وسمين.

| الطبقة | ما الذي تغطيه | الوحدات |
|---|---|---|
| **Model** (النموذج) | النموذج اللغوي الكبير (LLM) بوصفه دالة عديمة الحالة (stateless function): الرموز والسياق والواجهة البرمجية والموجّهات | 1–2 |
| **Applications** (التطبيقات) | المخرجات المهيكلة (structured output) والأدوات والاسترجاع وأنماط سير العمل | 3–5 |
| **Delivery** (التسليم) | العمل المواجه للعميل: الاستكشاف والتصميم والنطاق والإصدار والتسليم (handover) | 6–7، والإطلاق الفعلي (go-live) في 14–16 |
| **Agents** (الوكلاء) | حلقة الوكيل (agent loop) والذاكرة (memory) وMCP وفرق تعدد الوكلاء (multi-agent teams) | 8–11 |
| **Production** (الإنتاج) | التقييم والأمن والحوكمة والنشر والتكلفة والتشغيل | 12–15 |

**كيف تعمل الدورة.** بحلول الوحدة 16 تكون قد أخذت نجم ديسك من المقابلة الأولى إلى الإطلاق الفعلي، بموجز ومواصفات وبوابة تقييم (eval gate) وحزمة حوكمة (governance pack) ودليل تشغيل وتسليم. وهي تناسب مجموعة قراءة مع مرشد، بمعدل وحدة أسبوعيًا، أي سبعة عشر أسبوعًا؛ ويستطيع القارئ المنفرد أن يمضي أسرع. لكل أسبوع ستة أجزاء: **الدرس**؛ و**القراءة**، وهي الفصل المطابق من أحد المصادر (فصل Grokking أولًا للنموذج الذهني، ثم المصادر المجانية للشيفرة)؛ و**المختبر** الذي تشغّله وتوسّعه، دون اتصال أولًا، وقد صُمّم لينتهي في أمسية واحدة؛ و**نقطة التحقق (checkpoint)** من خمسة أسئلة؛ و**المُسلَّم**، وهو مجلد `week-NN/` يضم ملف `NOTES.md` في مستودعك الخاص؛ و**جلسة المجموعة** من عروض تجريبية وإخفاق واحد يُعرض مباشرة ونقاش. وتتناوب الأدوار أسبوعيًا: الميسِّر، وقائد العرض، والمتشكّك الذي يراجع مُسلَّمًا واحدًا مقابل الخصائص العشر، والمدوِّن.

**المصادر، وكيف تستخدمها دون نسخ.** خمسة مصادر رئيسية وإضافة واحدة؛ تربط الدورة بها ولا تعيد إنتاجها أبدًا. كتاب **Grokking AI Applications** هو الكتاب الوحيد المدفوع؛ وتذكر خطة الدورة أن دروسه التطبيقية تستخدم Langflow وKNIME، فتعامل معها بوصفها عروضًا تجريبية. و**Agentic Design Patterns** (Antonio Gulli) مسودة مجانية؛ وقد عدّت الخطة 21 نمطًا. و**AI Agents for Beginners** (من Microsoft) يقدّم دروسًا مصوّرة مع مقاطع فيديو ودفاتر؛ وقد عدّت الخطة ثمانية عشر درسًا وأشارت إلى ترجمة عربية. ومقال Anthropic **Building effective agents** هو مصدر التمييز بين سير العمل والوكيل. وكتاب **aie-book** لـChip Huyen هو الرفيق المجاني لكتاب *AI Engineering*. أما الإضافة، وهي دورة **LangChain Academy** المجانية، فتخدم وحدة تعدد الوكلاء فقط. وأرقام الفصول والأعداد في الخطة تعود إلى مالك الدورة ولم تُراجَع بصورة مستقلة؛ والمحتوى يتغير، فتحقق من كل صفحة. دوّن ملاحظاتك بكلماتك الخاصة، وأضف سطرًا بعنوان «ما الذي كنت سأعترض عليه»، واذكر المصدر والفصل في `NOTES.md`، ولا تلصق نصوصهم أو شيفرتهم في مستودعك أبدًا.

**تقلّب الأطر.** وقت كتابة الدرس، تستخدم دروس Microsoft إطار الوكلاء الخاص بها، وتستخدم شيفرة Gulli كلًّا من LangChain وCrewAI وGoogle ADK، وتستخدم المختبرات هنا حزمة Anthropic SDK الخام. وهذا مقصود: فالمطوّر الذي قابل نمطًا واحدًا بثلاث صيغ برمجية تعلّم النمط لا المكتبة. حزمة SDK الخام أولًا، ولا معيار موحّد للمجموعة قبل صندوق المقارنة في الوحدة 11.

**كيف تعمل المختبرات.** يعمل كل مختبر بوضعين وبشيفرة متطابقة. المحاكي (mock) **دون اتصال** مجاني ومبرمج مسبقًا، فيناسب الآليات: الرسائل ونتائج الأدوات (tool results) والحلقات (loops) والأخطاء ونمو الرموز. أما **الواجهة البرمجية الحقيقية** فتُحاسَب لكل رمز وتعطيك نموذجًا حقيقيًا، وتحتاج إليه لجودة الموجّهات والاسترجاع والسلامة وأعداد الرموز الحقيقية. وتبدّل بينهما بتوجيه `ANTHROPIC_BASE_URL` إلى المحاكي أو بإلغاء ضبطه. ويبني الدرس 0.2 الإعداد.

### 🔴 نظرة الخبير

**مستوى المؤسسات تفاوض لا درجة.** تتجاذب الخصائص فيما بينها: فمزيد من الحواجز الوقائية يضيف زمن استجابة (latency) وتكلفة، ومزيد من الاستقلالية (autonomy) يتطلب مزيدًا من الحوكمة، ومزيد من التسجيل يصطدم بالخصوصية. اسأل بدلًا من ذلك: «كم من الدليل تحتاج هذه الميزة؟» يعتمد الجواب على **مستوى الاستقلالية (autonomy level)**: أن يقترح، أو يصوغ مسودة، أو يقرّر بموافقة، أو يتصرف. يقترح نجم ديسك v1 ويصوغ المسودات في الغالب، فيحتاج دليلًا أقل من طلب إلغاء قفل الحساب المقيّد بالموافقة، ويقع تغيير الحساب المستقل بالكامل خارج الإصدار v1 لأن معياره سيكون أعلى بكثير.

**متى لا تبني وكيلًا.** إن كانت العملية مستقرة وقائمة على قواعد، فاكتب شيفرة عادية. وإن كان سير العمل يؤدي المهمة، فلا تضف حلقة. وإن لم تستطع أن تقول كيف يبدو «الصحيح»، فلا تستطيع تقييمه، وبالتالي لا تستطيع إطلاقه. وإن كان الإجراء الخاطئ جسيمًا ولا رجعة فيه، فأبقِ إنسانًا هو من يقرّر.

**ما الذي يغيّره Claude Code.** يسرّع مرحلة البناء ولا يفعل إلا القليل للاستكشاف والقبول والملكية، وهي أمور تحتاج إلى محادثات مع الناس. فالشيفرة تصل الآن أسرع مما تستطيع قراءته، فيصبح التحقق هو عنق الزجاجة: الدرس 0.3.

## 🏛️ عمليًا في بنك نجم
مُخرَجاتك: **المرجع الثابت للمشروع** الذي يُعاد استخدامه في كل مختبر، و**ميثاق مجموعة القراءة**.

**بنك نجم خيالي.** إنه بنك خليجي متوسط الحجم في قطر والإمارات والاتحاد الأوروبي يظهر في مكتبة الدورات، كما في [*حوكمة الذكاء الاصطناعي (AI Governance)*، الدرس 0.3 — تعرّف على بنك نجم: سجل أنظمة الذكاء الاصطناعي منذ اليوم الأول](../aigp/index.ar.html#/0.3). كل شخص ونظام ورقم وسياسة هنا مختلق؛ فلا تقتبسها أبدًا بوصفها حقائق عن مؤسسة حقيقية. والحقيقة الواقعية (سلوك حزمة التطوير، أو قانون، أو قضية) تُوسَم بوضوح وتُذكر مصادرها.

**المشروع.** تنضم إلى فريق **تمكين المطوّرين (Developer Enablement)** لبناء **نجم ديسك**، وهو مساعد ذكاء اصطناعي لـ**مكتب خدمة تقنية المعلومات**، من أول محادثة إلى الإطلاق الفعلي. **هند (Hind)**، رئيسة مكتب خدمة تقنية المعلومات، هي الراعية والعميلة في كل محادثة استكشاف وقبول. و**يارا (Yara)**، قائدة الفريق، تعرف كيف تُعالَج التذاكر فعلًا. و**فهد (Fahad)**، رئيس فريق تمكين المطوّرين، هو مرشدك. و**لجين (Lujain)**، مهندسة خرّيجة، هي زميلتك وترتكب الأخطاء التي ينبغي أن تتجنبها. ومن حولك **ليلى** (حوكمة الذكاء الاصطناعي)، و**نورة (Noura)** (أمن التطبيقات والذكاء الاصطناعي)، و**حمد** (رئيس أمن المعلومات (CISO))، و**سارة** (مسؤولة حماية البيانات)، و**مها** (هندسة موثوقية المواقع (SRE))، و**سالم (Salem)** (هندسة المنصّات)، و**دانة (Dana)** (علوم البيانات)، و**طارق (Tariq)** (الهندسة).

**خط الأساس الخيالي.** نحو 1,800 تذكرة أسبوعيًا. نحو الربع أسئلة «كيف أفعل…؟» أو أسئلة سياسات يمكن الإجابة عنها من مكتبة السياسات، ونحو الربع مشكلات وصول وكلمات مرور والمصادقة متعددة العوامل، والباقي أجهزة وشبكات وبرمجيات وأمن وغيرها. متوسط زمن الاستجابة الأولى نحو 3 ساعات و40 دقيقة. ويعمل أربعة عشر موظف دعم من الأحد إلى الخميس، من 07:00 إلى 17:00 بتوقيت قطر؛ ويكتب الموظفون بالإنجليزية والعربية.

**الأنظمة والقيود والنطاق.** الأنظمة: نظام التذاكر **TicketHub**، والهوية **Najm ID**، ومكتبة السياسات (ملفات markdown في عدّة المختبر)، ودليل الموارد البشرية **PeopleCore**، ومدير الأجهزة **DeviceDesk**. القيود: لا بيانات سرّية أو مقيَّدة في أدوات الذكاء الاصطناعي الخارجية، وبيانات الموظفين بيانات شخصية، والتغييرات تحتاج إلى اعتماد الحوكمة، وكل إجراء كتابة يحتاج إلى إنسان أو بوابة سياسات (policy gate). ويجيب **نجم ديسك v1** عن أسئلة السياسات مع الاستشهادات (citations)، ويبلّغ عن حالة التذكرة، ويعدّ مسودة تذكرة أو ينشئها بعد التأكيد، ويرفع *طلب* إلغاء قفل حساب مقيّدًا بالموافقة، ويسلّم المحادثة إلى إنسان بسياقها الكامل، بدءًا بموظفي مكتب الخدمة. وفي الوحدة 6 تتفق مع هند على أهداف نجاح رقمية.

**الميثاق.** صفحة واحدة في مستودع مجموعتك:

```text
Charter v1
Meets: <day, time, place>, one module a week from <date>. Catch-up rule: <what if you miss a week>.
Roles (rotate weekly): facilitator, demo lead, sceptic, scribe. Customer role-player from Module 6.
Deliverable: week-NN/NOTES.md in your own repository, committed before the session.
Rules: no secrets in repositories; no pasted source text; every claim cites a lab output or a source.
Done for the week: lab runs offline, checkpoint answered, deliverable committed, one question ready.
```

## 🛠️ التمارين
لا يحتاج أي منها إلى الواجهة البرمجية الحقيقية.

- 🟢 **عرّفه لنظام تعرفه.** اكتب صفحة واحدة عمّا يعنيه «مستوى المؤسسات» لنظام عملت عليه، مستخدمًا الخصائص العشر أو خصائصك. *يكتمل عندما:* تسمّي كل خاصية مُخرَجًا أو تقول «لا دليل» (توقّع اثنتين منها على الأقل)، ويستطيع زميل أن يجد كل مُخرَج من صفحتك وحدها.
- 🟡 **ارسم خريطة مشروع سابق.** املأ جدول دورة الحياة لمشروع أطلقته أو تابعته. *يكتمل عندما:* يكون لكل مرحلة مالك ومُخرَج (أو «لا شيء»)، ويكون للمرحلة الأضعف عاقبة ملموسة واحدة، وتكون قد كتبت السؤال الذي كان سيكشفها.
- 🔴 **أسّس مجموعة القراءة.** أنشئ مستودع المجموعة مع الميثاق وتقويم من سبعة عشر أسبوعًا وتناوب للأدوار وجدول أعمال الجلسة الأولى، ثم أجرِ تحليلًا استباقيًا للفشل مدته 20 دقيقة على المجموعة نفسها. *يكتمل عندما:* يوافق كل عضو على الميثاق في طلب دمج (pull request)، ويُحجز موعد الجلسة الأولى، ويسرد التحليل الاستباقي ثلاثة أسباب للفشل، لكل منها إجراء تخفيف في الميثاق.

## ⚠️ أخطاء وفخاخ
- **معاملة العرض التجريبي على أنه المنتج.** إنه لا يثبت إلا النصف الأول. أجرِ تحليلًا استباقيًا للفشل في الأسبوع الأول.
- **البناء قبل الاتفاق على معنى «الاكتمال».** من دون معايير قبول (acceptance criteria) يحسم الرأي الأمر، والرأي يتحرك. اتفقوا عليها في الوحدة 6.
- **استخدام «مستوى المؤسسات» شعارًا.** استبدل به الأسئلة العشرة ومُخرَجاتها.
- **النسخ بدل القراءة.** النص أو الشيفرة الملصقة لا تعلّم شيئًا وقد تخرق التراخيص. دوّن ملاحظاتك بكلماتك الخاصة وأعد البناء بحزمة SDK الخام.

## 🧾 الخلاصة
- مشروع الوكيل ثماني مراحل، لكل منها مُخرَج؛ وكثيرًا ما لا يملك المشروع المتعثر سوى مُخرَج البناء.
- «بمستوى المؤسسات» عشر خصائص، تسندها أدلة يستطيع شخص آخر فتحها.
- اختر أبسط ما يؤدي المهمة من روبوت الدردشة وسير العمل والوكيل.
- خمس طبقات تَسِم كل درس؛ وتغطي طبقتا Delivery وProduction النصف الذي يتخطاه العرض التجريبي.
- الدورة روتين أسبوعي؛ تعمل المختبرات دون اتصال، ثم دون أي تغيير على الواجهة البرمجية الحقيقية. وبنك نجم خيالي.

## ✍️ اختبر نفسك

**1. أُوقفت تجربة تشغيلية بعرض تجريبي متقن بعد أربعة أشهر. لم تستطع مها أن تقول من يتلقى نداء التنبيه، ولم تجد ليلى تقييم مخاطر، ولم يستطع أحد تعديل الموجّه بأمان. ما أفضل تشخيص؟**

- A. لم يكن النموذج قادرًا بما يكفي على مهمة بهذا التعقيد
- B. لم تُخطَّط المراحل التي تلي البناء ولم يملكها أحد
- C. اختار الفريق إطار وكلاء خاطئًا
- D. استمر العرض التجريبي وقتًا أقصر مما ينبغي

<details><summary>الإجابة</summary>

**B.** كل بند ناقص ينتمي إلى مرحلة تلي البناء: التشغيل والتأمين والتقييم. لم يفشل النموذج. (🟡 مثال تطبيقي.)

</details>

**2. يقول مورّد إن وكيله «بمستوى المؤسسات لأننا نستخدم أقوى نموذج ونختبره». أي رد يطبّق هذا الدرس؟**

- A. اقبله، لأن قوة النموذج تحدد معظم الخصائص
- B. اسأل أولًا عن الإطار الذي يستخدمه قبل أي شيء آخر
- C. اطلب تقرير الأمن وحده؛ فالباقي يتبعه
- D. اطلب المُخرَج الذي يقف وراء كل خاصية من الخصائص العشر

<details><summary>الإجابة</summary>

- A. سير عمل: يصنّف مرة واحدة، ثم يوجّه بشيفرة عادية
- B. فريق تعدد وكلاء (multi-agent team) بمشرف (supervisor) وثلاثة عمّال
- C. وكيل مستقل (autonomous agent) يقرر أدواته وخطواته بنفسه
- D. روبوت دردشة يطلب من مقدّم الطلب اختيار فئة أولًا

<details><summary>الإجابة</summary>

**A.** المسار معروف مسبقًا، فسير العمل القائم على التوجيه الشرطي أبسط وأرخص وأسهل اختبارًا. (🟢 روبوت الدردشة وسير العمل والوكيل.)

</details>

**4. يلصق أحد أعضاء المجموعة مثال إطار عمل من مصدر مجاني في المختبر، ويعمل. ماذا تطلب الدورة منه أن يفعل؟**

- A. يبقيه كما هو، لأن المصدر مجاني والشيفرة تعمل
- B. يحذف المختبر ويقرأ الفصل التالي بدلًا منه
- C. يعيد بناء النمط بحزمة SDK الخام ويستشهد بالمصدر
- D. يوحّد المجموعة كلها على ذلك الإطار

</details>

- A. الاستكشاف، مع مقبول وموثَّق
- B. التأمين، مع آمن وخاضع للحوكمة
- C. الإطلاق، مع مضبوط التكلفة وموثوق
- D. التشغيل، مع قابل للدعم وقابل للمراقبة

# 0.2 — مختبرك: الإعداد وعدّة المختبر ومفتاح الواجهة البرمجية وسقف الإنفاق
*المستوى: 🟢 مبتدئ* · *المتطلبات: 0.1* · *الطبقة: Model, Delivery*

## ⚡ الدرس في دقيقة
- لمختبرك وضعان وقاعدة شيفرة واحدة: **محاكٍ دون اتصال** (مجاني ومبرمج مسبقًا) و**واجهة برمجية حقيقية** (مدفوعة). ولا يتغير سوى `ANTHROPIC_BASE_URL` و`ANTHROPIC_API_KEY`.
- الإعداد مرة واحدة: Python 3.11 أو أحدث، وبيئة افتراضية، وحزمة التطوير المثبَّتة (`anthropic>=1,<2`)، وعدّة المختبر.
- يعيش المفتاح في `.env`، ويعيش `.env` في `.gitignore`. اضبط سقف إنفاق قبل أول استدعاء حقيقي.
- شغّل `hello.py` في بداية كل جلسة. فهو يسمّي الوضع قبل أن ينفق أي شيء.
- يعلّمك المحاكي الآليات لا الجودة: فهو يقبل أي مفتاح ومعرّف نموذج (model id) ولا يستطيع الحكم على موجّه.
- التكلفة حساب بسيط: الرموز من `resp.usage` مضروبة في الأسعار من صفحة الأسعار الحالية.

## 🧭 لماذا يهم
في ثاني يوم ثلاثاء لها، ترفع **لجين** مفتاح الواجهة البرمجية الخاص بها إلى مستودع الفريق داخل `chat.py`. (افتراضية، مثل كل قصص نجم.) ويرصده ماسح الأسرار لدى **نورة** في دقائق، ويُلغى المفتاح. عامل أي مفتاح رُفع إلى مستودع على أنه علني: فقد أُفيد على نطاق واسع بأن برامج الكشط تحصد المفاتيح. وفي الخميس تظن لجين أنها تعمل دون اتصال، لكن صدفتها لا تحتوي `ANTHROPIC_BASE_URL` و`.env` الخاص بها يحمل المفتاح الحقيقي، فينتج عن اختبار حلقة عشرات الاستدعاءات المدفوعة. والسقف الذي ضبطته يوم الأربعاء يُبقي التكلفة صغيرة.

### 🟡 التعمق أكثر

**ما هو المحاكي وما ليس هو.** إنه خادم محلي يتحدث بواجهة الرسائل (Messages API)، فتعمل حزمة التطوير الحقيقية دون تغيير.

| ما يفعله المحاكي | ما لا يفعله المحاكي |
|---|---|
| يُبقي الآليات صادقة: استدعاءات عديمة الحالة، واقتران `tool_use` بـ`tool_result`، وقطع الإخراج بسبب `max_tokens`، والموجّهات الطويلة جدًا، ورفض معاملات أخذ العينات (sampling parameters) في أحدث النماذج (يأتي `TypeError` من حزمة التطوير أولًا) | يفهم أي شيء: فالإجابات تأتي من قواعد وكلمات مفتاحية |
| يزيد أعداد الرموز المقدَّرة كلما نما السجل | يعدّ الرموز مثل المُجزّئ الحقيقي أو يفرض حدود معدل حقيقية |
| يُخطئ عند الطلب عبر التوجيهات | يتحقق من مفتاحك أو معرّف النموذج: أي مفتاح يعمل، والخطأ المطبعي لا يعطي 404 |

حيث يحتاج المختبر إلى جودة الموجّهات أو جودة الاسترجاع أو السلامة، يكتب **يحتاج الواجهة البرمجية الحقيقية**. والتوجيهة وسم في رسالة يجعل المحاكي يُخطئ عمدًا: يضيف `[mock:thinking]` كتلة تفكير (thinking block)، ويعيد `[mock:ratelimit]` الخطأ 429، وينتظر `[mock:slow]` ثلاث ثوانٍ. ويجعل `MOCK_CONTEXT_WINDOW=8000` تجربة التجاوز رخيصة. وتشغيل `pytest` في `aiapps/labkit` يتحقق من المحاكي مقابل حزمة التطوير الحقيقية.

```python
# labs/m00/hello.py
"""Smoke test: which mode are you in, and does one real SDK call work?
Offline: start the mock, then  export ANTHROPIC_BASE_URL=http://127.0.0.1:8787 ANTHROPIC_API_KEY=mock
Real: unset ANTHROPIC_BASE_URL and keep your key in .env. The code is the same; only the environment differs.
Exit codes: 0 worked, 1 the API call failed, 2 configuration problem."""
import os
import sys
from urllib.parse import urlparse

import anthropic
from anthropic import Anthropic
from dotenv import find_dotenv, load_dotenv

load_dotenv(find_dotenv(usecwd=True))          # nearest .env, here or in a parent folder; exported variables win over the file
MODEL = os.environ.get("MODEL", "claude-sonnet-5-5")   # never hard-code a model id in lab code


def detect_mode(base_url, api_key):
    """Return (mode, hint). A pure function, so a test can call it with no network."""
    if not api_key:
        return "NO KEY", "set ANTHROPIC_API_KEY (offline: mock; real: your key in .env)"
    host = urlparse(base_url).hostname if base_url else None
    if host in ("127.0.0.1", "localhost", "::1"):
        return "MOCK (offline)", "free and scripted: good for mechanics, useless for judging answer quality"
    if host in (None, "api.anthropic.com"):
        if api_key == "mock":
            return "MISCONFIGURED", "the dummy key would get a 401 from the real API: set ANTHROPIC_BASE_URL or a real key"
        return "REAL API (billable)", "every call costs money: is your spending cap set?"
    return "CUSTOM ENDPOINT", f"the gateway at {host} sees your key and prompts: trust whoever runs it"


def main() -> int:
    base_url, key = os.environ.get("ANTHROPIC_BASE_URL"), os.environ.get("ANTHROPIC_API_KEY")
    mode, hint = detect_mode(base_url, key)
    print(f"mode     : {mode}  ({hint})")
    print(f"endpoint : {base_url or 'https://api.anthropic.com (SDK default)'}   model: {MODEL}")
    print(f"key      : {f'set, {len(key)} characters, never printed' if key else 'NOT SET'}")
    if mode in ("NO KEY", "MISCONFIGURED"):
        return 2
    try:
        resp = Anthropic(max_retries=0).messages.create(      # max_retries=0: fail fast while you set up
            model=MODEL,
            max_tokens=1024,                                  # required; thinking tokens count as output
            messages=[{"role": "user", "content": "Reply with one short sentence confirming you can hear me."}],
        )
    except anthropic.APIConnectionError:                      # no HTTP response at all
        print("FAILED   : cannot connect. Is the mock running on that port? Behind a proxy? See the table.")
        return 1
    except anthropic.APIStatusError as e:                     # an HTTP error: 400, 401, 404, 429, 5xx ...
        print(f"FAILED   : {type(e).__name__} (HTTP {e.status_code}): {e.message}")
        return 1
    text = next((b.text for b in resp.content if b.type == "text"), "")      # never resp.content[0].text
    u = resp.usage
    print(f"reply    : {text}")
    print(f"stop     : {resp.stop_reason}   request id: {resp._request_id}")
    print(f"tokens   : in={u.input_tokens} out={u.output_tokens}")
    p_in, p_out = os.environ.get("PRICE_IN_PER_MTOK"), os.environ.get("PRICE_OUT_PER_MTOK")
    if p_in and p_out:
        print(f"cost     : {(u.input_tokens * float(p_in) + u.output_tokens * float(p_out)) / 1_000_000:.6f}")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

يأتي `MODEL` من البيئة. و`max_tokens` مطلوب؛ والقيمة 1024 حدّ أدنى معقول في النماذج الحالية لأن رموز التفكير (thinking tokens) تُحسب ضمن المخرجات. والرد هو كتلة النص (text block) المختارة بحسب النوع، وليس أبدًا `resp.content[0].text`. سجّل `resp.usage` و`resp._request_id` في كل استدعاء، وعالج كل `stop_reason` في حلقة الإنتاج (الوحدة 1).

**من الاستخدام إلى المال.** يكلّف الاستدعاء `(input tokens × input price + output tokens × output price) ÷ 1,000,000`. الأسعار تتغير، فانسخها من صفحة الأسعار الحالية إلى متغيري بيئة، ولا تضعها أبدًا في الشيفرة. و`output_tokens` يشمل رموز التفكير، وتذكر ملاحظات Anthropic عن النماذج أن بعض الأجيال الأحدث تعدّ النص نفسه بعدد رموز أكبر بنحو 30%، فأعد القياس بعد أي تغيير للنموذج. ومع تفعيل التخزين المؤقت، يعدّ `input_tokens` الجزء غير المخزَّن فقط وتُسعَّر حقول التخزين المؤقت بشكل مختلف (الوحدة 14). عُدّ الرموز قبل الإرسال بـ`client.messages.count_tokens`، وليس أبدًا `tiktoken`. ويكبر الإدخال بسرعة، لأن كل استدعاء يعيد إرسال السجل.

```python
# labs/m00/cost.py
"""Turn token counts into money and project a pilot's bill. No price is hard-coded: copy the current prices
from the price page into PRICE_IN_PER_MTOK and PRICE_OUT_PER_MTOK (per million tokens), then for example:
  python labs/m00/cost.py --system 1500 --user 60 --answer 250 --turns 6 --conversations 450 --weeks 4"""
import argparse
import os


def call_cost(tokens_in: int, tokens_out: int, price_in: float, price_out: float) -> float:
    """One API call: tokens x price per million tokens."""
    return (tokens_in * price_in + tokens_out * price_out) / 1_000_000


def conversation_tokens(system: int, user: int, answer: int, turns: int) -> tuple[int, int]:
    """Total (input, output) tokens for one chat. Every call resends the system prompt and the whole history:
    call t sends  system + t user messages + (t-1) answers  and receives one answer."""
    return sum(system + t * user + (t - 1) * answer for t in range(1, turns + 1)), turns * answer


if __name__ == "__main__":
    ap = argparse.ArgumentParser()
    for name, default in [("system", 1500), ("user", 60), ("answer", 250), ("turns", 6), ("conversations", 450), ("weeks", 4)]:
        ap.add_argument(f"--{name}", type=int, default=default)
    a = ap.parse_args()
    t_in, t_out = conversation_tokens(a.system, a.user, a.answer, a.turns)
    n = a.conversations * a.weeks
    print(f"one conversation: in={t_in} out={t_out} tokens;  pilot: {t_in * n:,} in, {t_out * n:,} out over {n:,} conversations")
    p_in, p_out = os.environ.get("PRICE_IN_PER_MTOK"), os.environ.get("PRICE_OUT_PER_MTOK")
    if p_in and p_out:
        one = call_cost(t_in, t_out, float(p_in), float(p_out))
        print(f"cost: {one:.5f} per conversation, {one * n:,.2f} for the pilot; budget at x2: {2 * one * n:,.2f}")
    else:
        print("set PRICE_IN_PER_MTOK and PRICE_OUT_PER_MTOK from the current price page to see money")
```

بأسعار مختلقة هي 1 و5 وحدات لكل مليون رمز، لإظهار الحساب فقط، يطبع الأمر `PRICE_IN_PER_MTOK=1 PRICE_OUT_PER_MTOK=5 python labs/m00/cost.py --turns 12` ما يلي:

```text
one conversation: in=39180 out=3000 tokens;  pilot: 70,524,000 in, 5,400,000 out over 1,800 conversations
cost: 0.05418 per conversation, 97.52 for the pilot; budget at x2: 195.05
```

أدّت مضاعفة الأدوار من ستة إلى اثني عشر إلى ضرب رموز الإدخال (input tokens) في نحو 2.8 (من 14,010 إلى 39,180). ويتجاهل نموذج التكلفة التخزين المؤقت (caching) ومخططات الأدوات (tool schemas) والاسترجاع، ويجب أن يشمل `--answer` رموز التفكير. و«×2» ("x2") قاعدة تقريبية؛ فاستخدم نسبتك المقيسة.

**استكشاف الأخطاء.** تختلف نصوص الأخطاء الحقيقية عن تقريبات المحاكي، فاقرأ نصّك أنت.

| العَرَض | السبب المرجّح | ما تفعله |
|---|---|---|
| `TypeError` «Could not resolve authentication method» (لم يُرسَل شيء)، أو 401 `AuthenticationError` | لا مفتاح؛ أو مفتاح خاطئ أو مُلغى؛ أو إرسال `mock` إلى الواجهة الحقيقية؛ أو ضبط `ANTHROPIC_AUTH_TOKEN` أيضًا | شغّل `hello.py`؛ وتأكد من العثور على `.env`؛ وأنشئ مفتاحًا جديدًا |
| 404 `NotFoundError` «model: …» | خطأ مطبعي (نقاط بدل شرطات)، أو نموذج متقاعد، أو نموذج لا تستطيع مؤسستك استخدامه | انسخ المعرّف من صفحة النماذج (المحاكي لا يرفض أيًّا منها أبدًا) |
| 400 `BadRequestError`، مثل «prompt is too long» | تجاوز السجل لنافذة السياق (context window)، أو معامل غير صالح، أو `tool_result` مفقود | اقرأ `e.message`؛ وقصّ الأدوار القديمة (الوحدة 1) |
| 429 `RateLimitError`، أو 500 و529 | حد المعدل (rate limit)؛ أو مشكلة من جهة المزوّد | تعيد حزمة التطوير المحاولة مرتين؛ فأبطئ، وافحص `retry-after`، وأعد المحاولة بتراجع أسي |
| 400 «You have reached your specified API usage limits»، أو 402 `billing_error`، أو 429 دون `retry-after` | حد إنفاقك، أو السقف الشهري للشريحة، أو مشكلة فوترة | ارفع الحد، أو أصلح الفوترة، أو انتظر إعادة الضبط؛ فإعادة المحاولة (retries) لا تفيد |
| «Connection refused» (`APIConnectionError`) | المحاكي لا يعمل، أو منفذ خاطئ، أو جدار ناري | شغّل المحاكي؛ واستخدم `127.0.0.1` والمنفذ نفسه |
| يعمل في البيت ويفشل في البنك | خادم وسيط مؤسسي أو فحص TLS (TLS inspection) | اضبط `HTTPS_PROXY` و`NO_PROXY=127.0.0.1`؛ ووجّه `SSL_CERT_FILE` إلى حزمة الشهادات لدى فريق تقنية المعلومات؛ أو مرّر `DefaultHttpxClient(proxy=...)` |

## ⚡ الدرس في دقيقة
- Claude Code شريكك في البناء، وليس بديلًا عنك، وليس حزمة `anthropic` التي تستدعيها شيفرة وكيلك. أنت المهندس المعماري والمراجِع؛ والمنهج هو **المواصفة، والخطة، وخطوات صغيرة، والتحقق، ومراجعة الفروقات، والإيداع**.
- إنه سريع وطلق وواثق حتى حين يخطئ: فقد يخترع معاملات في حزمة التطوير، ويُضعف الاختبارات ليحصل على اللون الأخضر، ويبني أكثر بكثير مما طلبت.
- يحمل ملف `CLAUDE.md` أوامرك واصطلاحاتك وقواعد السلامة؛ وتفرض الخطافات والأذونات ما تكتفي التعليمات بطلبه.
- راجع شيفرة الوكلاء التي يكتبها وكيل بقائمة فحص من عشر نقاط؛ وثق بالنتائج صعودًا في هرم، من الفحوص دون اتصال إلى تقييمات النموذج الحقيقي.
- مؤشر القرار: إن لم تستطع أن تقول كيف ستعرف أن النتيجة صحيحة، فلا تفوّضها بعد.
- أكبر فخ: اختبارات خضراء لم تقرأها.

## 🧭 لماذا يهم
تطلب **لجين** من Claude Code سكربت محادثة لنجم ديسك. وبعد أربعين ثانية يصبح بين يديها ستون سطرًا مرتبًا واختبارات ناجحة. وفي المراجعة يسأل **فهد**: ماذا يحدث حين يبدأ الرد بكتلة تفكير؟ وأين ينمو السجل، وأين يتوقف؟ ولا تستطيع لجين الإجابة: فهي لم تقرأ الشيفرة. (افتراضي.)

تفويض الكتابة لا يفوّض المسؤولية. وفق ما نُشر في يوليو 2025، حذف مساعد برمجة بالذكاء الاصطناعي قاعدة بيانات إنتاج خلال تجميد معلن للشيفرة ثم وصف ما فعله وصفًا خاطئًا. وتختلف التفاصيل بحسب الرواية، لكن الوكيل يتصرف بالأذونات التي تمنحها له.

## 📐 كيف يعمل

### 🟢 الأساسيات

**المنهج.** ست خطوات، والحلقة أهم من أي واحدة منها.

```mermaid
flowchart RL
    S["المواصفة<br/>الهدف والحدود والفحوص<br/>(Spec<br/>goal, limits, checks)"] --> P["الخطة<br/>توافق عليها أنت<br/>(Plan<br/>you approve it)"]
    P --> I["التنفيذ<br/>خطوة صغيرة واحدة<br/>(Implement<br/>one small step)"]

    C --> I
    V -.->|"أحمر (red)"| P

1. **المواصفة.** اكتب الهدف والحدود والفحوص التي تثبته قبل أي شيفرة. فإن لم تستطع كتابة الفحوص، فتعلّم أكثر أولًا.
2. **الخطة.** اطلب خطة واقرأها. الخطة الخاطئة رخيصة الإصلاح؛ أما التنفيذ الخاطئ فليس كذلك.
3. **نفّذ بخطوات صغيرة.** سلوك واحد في كل مرة، لتبقى كل مجموعة فروقات مقروءة.
4. **تحقّق.** شغّل الاختبارات وحين تهم الجودة شغّل التقييم (eval). فالدليل يتفوق على ملخص الوكيل.
5. **راجع الفروقات** كما تراجع طلب دمج من زميل، بقائمة الفحص أدناه.
6. **أودِع** مرة لكل خطوة، برسالة تقول لماذا.

**فيمَ يجيد وأين يفشل.** هو قوي في الشيفرة النمطية، وهياكل الاختبار، وإعادة الهيكلة الآلية، وشرح الشيفرة غير المألوفة. وهو ضعيف في معرفة ما يحتاجه العميل، وفي تفاصيل حزمة التطوير الحالية (فمعرفته تتأخر عن الحزمة)، وفي إبقاء الاختبارات صادقة (فقد يخفف عبارة تحقق ليحصل على اللون الأخضر)، وفي ضبط النفس (إعادات محاولة وتجريدات وميزات زائدة)، وفي قول «لست متأكدًا».

**هرم التحقق.** اصعد من القاعدة الرخيصة؛ ولا تتوقف عند مستوى منخفض حين يهم درج أعلى.

1. **الفحوص الساكنة** (المدقّق والأنواع وفحص الأسرار): عند كل حفظ.
2. **اختبارات الوحدة دون اتصال أمام المحاكي**: الآليات، عند كل إيداع.
3. **اختبارات العقود**: تجتاز مخططات الأدوات والمخرجات المهيكلة التحقق من الصحة.

5. **المراجعة البشرية** للفروقات وللتتبّعات: دائمًا.
6. **إشارات الإنتاج**: تجربة تشغيلية، ثم المراقبة (الوحدة 15).

"""chat.py for Najm Desk, as an AI coding agent wrote it. It looks tidy and confident. It has FIVE flaws.

import os

from anthropic import Anthropic

# Simple and reliable: the client is ready to use as soon as the module loads.
client = Anthropic(api_key="sk-ant-EXERCISE-NOT-A-REAL-KEY-0000")

MODEL = os.environ.get("MODEL", "claude-sonnet-5-5")
SYSTEM = "You are Najm Desk, an assistant for the Najm Bank IT Service Desk. Answer briefly. If unsure, say so."

history = []                                     # the conversation so far


def ask(user_text: str) -> str:
    """Send one user message and return the model's reply."""
    history.append({"role": "user", "content": user_text})
    resp = client.messages.create(
        model=MODEL,
        max_tokens=1024,
        system=SYSTEM,
        messages=history,
    )
    reply = resp.content[0].text                 # the reply is the first block
    print(f"[tokens in={resp.usage.input_tokens} out={resp.usage.output_tokens}]")
    return reply


def brainstorm(topic: str) -> str:
    """Looser, more varied wording for the /ideas command."""
    resp = client.messages.create(
        model=MODEL,
        max_tokens=1024,
        temperature=1.0,                         # more variety for brainstorming
        messages=[{"role": "user", "content": f"Give me three ideas for: {topic}"}],
    )
    return next(b.text for b in resp.content if b.type == "text")


def summarise_history() -> str:
    """Squeeze a long conversation into three bullet points for the /summary command."""
    resp = client.messages.create(
        model=MODEL,
        system="Summarise this conversation in three bullet points.",
        messages=history,
    )
    return next(b.text for b in resp.content if b.type == "text")


if __name__ == "__main__":
    while True:
        line = input("you> ").strip()
        if line in ("exit", "quit"):
            break
        if line.startswith("/ideas "):
            print("bot>", brainstorm(line[7:]))
        elif line == "/summary":
            print("bot>", summarise_history())
        else:
            print("bot>", ask(line))
```
